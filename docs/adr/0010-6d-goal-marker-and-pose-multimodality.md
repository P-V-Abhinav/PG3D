# ADR 0010: 6D oriented goal marker and null-space pose multimodality

- Status: Accepted
- Date: 2026-08-30
- Deciders: pg3d maintainers

## Context

The pose-reach dataset generator (`scripts/write_maniskill_pose_reach_dataset.py`)
produced strong **path** multimodality (trajectory families that travel from A to
B along different routes) and covered many goal orientations, but had two gaps for
6D pose reaching:

1. **Orientation-blind goal marker.** The baked goal marker
   (`pg3d/policies/dp3/goal_markers.py`) was a rotationally symmetric sphere/cross/ring
   centered on the goal *position* only. The DP3 encoder splits the trailing
   `goal_marker_points` slots into a dedicated ordered MLP
   (`goal_marker_mlp` in `pg3d/policies/dp3/modules.py`), but a symmetric marker
   carries zero orientation signal, so the policy had no observable target
   orientation to condition on.

2. **No pose multimodality.** For a fixed start and a fixed 6D goal pose, every
   trajectory family reached the *same* final arm configuration. The 7-DOF arm's
   redundancy (a 1-DOF self-motion manifold for a 6-DOF task) was never exploited,
   so the dataset never demonstrated *multiple ways to attain the same pose*.

Separately, the orientation set was generated by a pole-biased equal-*angle* tilt
grid (`_build_cone_orientations`), which over-sampled straight-down and starved the
rim of the cone.

## Decision

### Single correct wrist orientation
Each goal has exactly one correct wrist orientation. We do **not** model the
gripper 0deg/180deg flip case: no C2/roll-symmetric marker, no U/fork marker, and
no gripper-flip generation. Pose multimodality is purely **null-space
configuration** multimodality (different elbow/shoulder solutions that keep the
same wrist pose).

### Oriented triad goal marker (`triad`)
The new default marker is an asymmetric coordinate-frame **triad**: a dense origin
cluster plus three one-sided arms of **distinct lengths** (X longest, Y medium, Z
shortest), rigidly transformed by the goal `(position, quaternion)`. Distinct
lengths + one-sided arms give the marker **no rotational symmetry**, so any nonzero
rotation (including a 180deg roll about any axis) yields a different ordered point
set. Because the encoder's goal branch is an *ordered* MLP, orientation is directly
learnable.

We rejected the plain **U/fork** shape because its C2 symmetry is uncontrolled: a
0deg and a 180deg-rolled pose produce an identical marker, reintroducing the exact
mode-averaging ambiguity we are trying to remove.

The legacy position-only `sphere` marker is retained as a selectable style
(`--goal-marker-style {sphere,triad}`, default `triad`) for ablation and backward
comparison.

### Encoder compatibility
The total `goal_marker_points` slot count is unchanged (default 192), so the
`goal_marker_mlp` input dimension (`goal_marker_points * 3`) is unchanged. Existing
DP3 checkpoints therefore load architecturally, **but must be retrained** because
the marker semantics changed (position-only -> full 6D pose).

### Equal-area orientation sampling
The pole-biased tilt grid is replaced by equal-area cone sampling:
`cos(theta) ~ U[cos(half_angle), 1]`, `phi ~ U[0, 2*pi)`, tilting a straight-down
base orientation. This fills the whole cone (including the rim) and improves with
data volume. Exposed as `--orientation-cone-half-angle-deg` (default 60, i.e. a
~120deg solid angle) and `--orientations-per-goal`. The first orientation per pose
is always exact straight-down.

### Null-space configuration sampler
`sample_nullspace_configs(...)` is robot-agnostic (Panda and xArm7 are both 7-DOF).
For a fixed 6D goal pose it reseeds the planner from jittered seed configs, plans to
the identical pose, keeps solutions whose final TCP pose matches within
`--config-match-position-tol-m` / `--config-match-orientation-tol-deg`, and dedups by
joint-space distance (`--config-min-joint-separation-rad`). Each accepted config is
expanded by the existing trajectory families (config x family cross-product), bounded
by `--configs-per-goal-pose` and `--max-configs-per-start-goal`.

## Data / observation changes

- New per-step `goal_quat` array (`[T, 4]`, SAPIEN `[w,x,y,z]`, episode-constant)
  is written as a dataset alias so inference can bake the identical triad. Old
  datasets without it gracefully fall back to the `sphere` marker.
- Marker construction is unified in `build_goal_marker` /
  `insert_goal_marker_points`, shared by the dataset writer and all inference-time
  bakers, so dataset and deployment never diverge.
- `SimpleDP3` gained a `goal_marker_style` attribute so rollout reads the marker
  style from the trained policy.

## Consequences

- Positive: the policy can condition on the full 6D goal pose; the dataset
  demonstrates multiple genuine arm solutions per pose; orientation coverage is
  unbiased over the cone.
- Cost: checkpoints trained on the old sphere marker must be retrained.
- Live fresh-seed triad rollout requires the caller to supply the goal quaternion
  (the env `goal_site` is position-only); dataset-sourced rollout reads it from the
  stored `goal_quat`.
- Null-space feasibility varies with position; diagnostics report *achieved*
  (feasible) coverage, not just attempted.

## Verification

- Pure-geometry unit tests (CPU-only, no simulator):
  - `tests/test_goal_markers.py` — triad asymmetry (incl. 180deg roll), exact point
    count, identity frame, rigid transform.
  - `tests/test_goal_marker_parity.py` — writer vs inference marker parity.
  - `tests/test_reach_dataset_triad.py` — end-to-end orientation sensitivity in
    `ReachSequenceDataset`.
  - `tests/test_orientation_sampler.py` — equal-area density (rim not starved),
    valid unit quats, within-cone.
  - `tests/test_nullspace_configs.py` — dedup, tolerance filtering with a fake
    planner.
  - `tests/test_diagnose_pose_multimodality.py` — config-count and cone-coverage
    diagnostics.
- Simulator-dependent paths (episode collection, live rollout) are wired but not
  run in CPU-only CI.
